# 작업 내용 정리 (2026-08-29)

기존 로그인/홈 화면 코드는 그대로 두고, 메뉴바(헤더 드롭다운)의 세 항목에 연결되는 화면 3개를 새로 만들었습니다.

| 메뉴 버튼 | 연결된 화면 | 참고 자료 |
|---|---|---|
| 도시락 조회 | `ApplicationScreen` (신청 화면) | 첨부 이미지 1 (신청 화면) |
| 식품 등록 | `RegisterScreen` (잉여 식품 등록) | 첨부 이미지 2 (잉여 식품 등록) |
| 마이페이지 | `MyPageScreen` (마이페이지) | 이미지 없음 → 일반적인 앱 마이페이지 구성을 참고해 임의 제작 |

---

## 1. App.js에 추가된 내용

기존 `LoginScreen` 아래, `App` 컴포넌트 export 위쪽에 새 컴포넌트들을 추가했습니다. 기존 `Header`, `Logo`, `AvatarPlaceholder`, `SearchBar`, `MapArea`, `HomeScreen`, `LoginScreen` 코드는 전혀 수정하지 않았습니다.

### 공용 부품 (여러 화면에서 재사용)
- **`PinBadge`** — 매장 사진 위에 얹히는 파란 동그라미 위치 마커(📍). 이미지 속 사진 위 파란 배지를 표현.
- **`Badge`** — 알레르기 등 강조 표시용 초록색 알약 모양 배지 (예: "복숭아").
- **`StoreCard`** — 매장 사진 + 이름 + 영업시간 + 주소 + 전화번호를 보여주는 카드. 신청 화면과 등록 화면에서 공통으로 사용.
- **`MenuCard`** — 메뉴 사진 + 메뉴 목록 + 알러지 주의 식품 배지를 보여주는 카드 (신청 화면 전용).
- **`TagInputGrid`** — "+" 버튼을 누르면 `window.prompt`로 텍스트를 입력받아 태그(칩) 형태로 추가하고, 각 태그 옆 `×` 버튼으로 삭제할 수 있는 입력 그리드 (등록 화면의 메뉴/알러지 식품 입력에 사용).

### 화면 1 — `ApplicationScreen` (도시락 조회 → 신청 화면)
- 헤더 + `StoreCard`(스타벅스 코엑스몰점 정보) + `MenuCard`(소불고기 등 메뉴, 복숭아 알러지 배지)
- "수령 시간을 입력하세요" 텍스트 입력창 (`useState`로 값 관리)
- 알레르기 책임 고지 체크박스 (`useState`로 체크 여부 관리)
- 하단 고정 버튼: `취소하기`(홈으로 이동) / `신청 하기`
  - 수령 시간이 비어있거나 체크박스에 동의하지 않으면 `신청 하기` 버튼이 비활성화(흐린 색) 상태가 됩니다.
  - 신청 완료 시 알림창을 띄우고 홈 화면으로 이동합니다.
- 헤더 드롭다운의 "도시락 조회"를 클릭하면 이 화면(`list` 키)으로 이동하도록 연결했습니다.

### 화면 2 — `RegisterScreen` (식품 등록 → 잉여 식품 등록)
- 헤더 + `StoreCard`(동일한 매장 정보 카드 재사용)
- 사진 업로드 박스 — 클릭하면 파일 선택창이 열리고, 이미지를 고르면 미리보기가 배경으로 표시됩니다. (`useRef`로 숨겨진 `<input type="file">`을 트리거)
- "메뉴를 입력하세요" — `TagInputGrid`로 메뉴 이름을 여러 개 추가/삭제 가능
- "수량을 입력하세요" — 텍스트 입력창
- "알러지 식품을 입력해주세요" — `TagInputGrid`로 알러지 유발 식품을 여러 개 추가/삭제 가능
- 하단 고정 버튼: `취소하기`(홈으로 이동) / `등록 하기`
  - 메뉴가 1개 이상 + 수량이 입력되어야 `등록 하기` 버튼이 활성화됩니다.
  - 등록 완료 시 알림창을 띄우고 홈 화면으로 이동합니다.
- 헤더 드롭다운의 "식품 등록"을 클릭하면 이 화면(`register` 키)으로 이동하도록 연결했습니다.

### 화면 3 — `MyPageScreen` (마이페이지) — 임의 제작
참고 이미지가 없어, 배달의민족/당근마켓 등 일반적인 서비스 앱의 마이페이지 구성(프로필 + 활동 통계 + 메뉴 목록 + 로그아웃)을 참고하여 이 앱의 디자인 톤에 맞게 새로 구성했습니다.
- 상단 프로필 카드: 아바타, 이름, 이메일, "프로필 수정" 버튼
- 활동 통계 3칸: 신청한 도시락 수 / 등록한 식품 수 / 나눔 참여일 (현재는 예시 숫자, 추후 실제 데이터 연동 필요)
- "내 활동" 메뉴 그룹: 신청 내역 / 등록 내역 / 찜한 매장
- "설정" 메뉴 그룹: 알림 설정 / 계정 관리 / 고객센터
- "로그아웃" 버튼 → 클릭 시 로그인 화면으로 돌아감
- 헤더 드롭다운의 "마이페이지"를 클릭하면 이 화면(`mypage` 키)으로 이동하도록 연결했습니다.

### App 컴포넌트 수정
`screens` 객체에 새 화면 3개를 추가했습니다.
```js
const screens = {
  login: <LoginScreen onNavigate={setPage} />,
  home: <HomeScreen onNavigate={setPage} query={query} setQuery={setQuery} />,
  list: <ApplicationScreen onNavigate={setPage} />,      // 신규
  register: <RegisterScreen onNavigate={setPage} />,     // 신규
  mypage: <MyPageScreen onNavigate={setPage} />,         // 신규
};
```
(헤더의 메뉴 항목 key는 원래 코드에 `list` / `register` / `mypage`로 이미 정의되어 있어 그대로 맞췄습니다.)

# 2차 작업 내용 정리 (2026-08-30)

마이페이지 메뉴 7개 각각의 세부 화면과, "소속 인증" 기능 + "식품 등록" 접근 제한을 추가했습니다.

## 5. 마이페이지 하위 화면 7개 신규 제작

모두 상단에 뒤로가기(←) + 제목이 있는 공용 상단바(`SubPageHeader`)를 쓰고, 뒤로가기를 누르면 마이페이지로 돌아갑니다. 마이페이지의 각 메뉴 항목 클릭 시 해당 화면으로 이동하도록 연결했습니다.

| 메뉴 | 컴포넌트 | 내용 |
|---|---|---|
| 프로필 수정 | `ProfileEditScreen` | 아바타 사진 변경, 이름/이메일/전화번호 입력 후 "저장하기" → 마이페이지에 즉시 반영 |
| 신청 내역 | `ApplicationsHistoryScreen` | 과거 신청한 도시락 목록(매장명, 날짜, 수령시간, 상태 배지: 수령완료/취소됨) — 예시 데이터 3건 |
| 등록 내역 | `RegistrationsHistoryScreen` | 과거 등록한 식품 목록(메뉴, 수량, 날짜, 상태 배지: 수령완료/마감됨/등록됨) — 예시 데이터 3건 |
| 찜한 매장 | `FavoritesScreen` | 찜한 매장 리스트, ♥ 버튼으로 찜 해제(목록에서 즉시 제거) — 예시 데이터 2건 |
| 알림 설정 | `NotificationSettingsScreen` | 픽업 알림 / 새 도시락 등록 알림 / 마케팅 수신 on-off 토글 스위치(`ToggleSwitch`) |
| 계정 관리 | `AccountScreen` | 로그인 방식, 이메일, 전화번호, 소속 인증 상태 표시 + 프로필 수정 바로가기 + 회원 탈퇴(확인창 후 로그인 화면으로) |
| 고객센터 | `SupportScreen` | 자주 묻는 질문 아코디언 4개 + "1:1 문의하기" 버튼 |

신청/등록 내역, 찜한 매장의 목록은 아직 백엔드가 없어 넣어둔 예시(mock) 데이터입니다. 실제 연동 시 서버에서 받아온 배열로 교체하면 됩니다.

## 6. 소속 인증 기능 + 식품 등록 접근 제한

- **`VerifyScreen`** (신규): 마이페이지 프로필 카드의 "🏷️ 소속 인증하기" 버튼으로 진입. 소속(매장/기관)명을 입력하고(인증 서류 첨부는 선택) "인증 신청하기"를 누르면 즉시 인증 완료 처리됩니다(백엔드 심사 없이 MVP 수준에서 바로 승인). 이미 인증된 상태라면 인증 완료 화면과 "인증 해제하기"(테스트용) 링크를 보여줍니다.
- **인증 마크 표시**: 인증된 사용자는
  - 마이페이지 프로필의 이름 옆에 파란색 "✓ 인증됨" 배지가 표시되고, 인증받은 소속명도 함께 표시됩니다.
  - 헤더(상단 우측) 프로필 아이콘 위에도 작은 파란 체크 배지가 표시됩니다.
- **"식품 등록" 접근 제한**: 소속 인증 여부(`verification.verified`)를 `App` 컴포넌트에서 상태로 관리하며 `Header`와 `RegisterScreen`에 props로 전달합니다.
  - 인증되지 않은 사용자에게는 헤더 드롭다운의 "식품 등록" 항목 옆에 🔒 아이콘이 표시됩니다.
  - 인증되지 않은 상태로 "식품 등록"에 진입하면 실제 등록 폼 대신 "소속 인증이 필요한 기능이에요" 안내 화면이 뜨고, "소속 인증하러 가기" 버튼으로 바로 인증 화면으로 이동할 수 있습니다.
  - 인증이 완료되면 잠금이 풀리고 원래의 잉여 식품 등록 폼이 정상적으로 보입니다.

## 7. App.js 상태 구조 변경 (props 전달 방식)

기존에는 각 화면이 자기 안에서만 상태를 관리했지만, 이번에는 마이페이지/헤더/식품등록 화면이 서로 같은 정보(프로필, 인증 여부)를 공유해야 해서 `App` 컴포넌트로 상태를 끌어올렸습니다(state lifting).

```js
const [profile, setProfile] = useState({ name: "", email: "", phone: "", avatar: null });
const [verification, setVerification] = useState({ verified: false, org: "" });
const [favorites, setFavorites] = useState([...]);
const [notifSettings, setNotifSettings] = useState({ pickup: true, newListing: true, marketing: false });
```

이 상태들과 변경 함수(`setProfile`, `onVerify`, `onUnverify`, `onRemoveFavorite`, `onToggle` 등)를 각 화면에 props로 내려주는 방식입니다. `Header`도 `verified`, `avatarUrl` prop을 받아 잠금 아이콘/인증 배지를 표시하도록 수정했습니다.

## 8. App.css 추가 클래스

`.subheader*`, `.subpage*`(하위 화면 공용 레이아웃), `.gate-screen*`/`.btn-text`(잠금 안내), `.verify-badge`/`.avatar-placeholder__badge`/`.header__dropdown-lock`(인증 마크), `.history-card*`/`.status-badge*`(내역 화면), `.favorite-card*`(찜한 매장), `.toggle-row*`/`.switch*`(알림 설정 토글), `.account-row*`/`.account-danger`(계정 관리), `.faq-item*`(고객센터), `.profile-edit__avatar*`(프로필 수정), `.verify-intro`/`.verify-done*`(소속 인증) 등을 파일 끝에 추가했습니다. 기존 클래스는 수정하지 않았습니다.
